# AGENTS.md

## Purpose

A benchmark of automated reviewers on changes to a synthetic regulated bank platform: 27 obligations, 270 changes, sealed answer keys, and published verdicts for seven reviewer configurations. Method and limits are in `PROTOCOL.md`; results in `RESULTS.md`; corrections in `CORRECTIONS.md`. This repository is public.

## Repo layout

- `platform/` - the synthetic bank platform (two apps, `controls/`, `ci/`)
- `obligations/` - catalog builder and citation check for the 27 obligations
- `bench/seeder/`, `bench/key/`, `bench/score/` - variant generator, sealed keys, scorer
- `baselines/` - frozen prompts, runners for every arm, fixtures, plumbing tests
- `variants/<split>/<id>/` - records and `repo.bundle` per change
- `runs/<split>/<arm>/` - one verdict file per change
- `RESULTS.md`, `reports/results.json` - regenerated by `scripts/results.py`
- `scripts/`, `docs/`, `shared/`

## Setup

```bash
sh scripts/setup_tools.sh               # pytest venv and the JUnit console jar under .tools/
python3 scripts/unpack_variants.py      # clone the 270 variant bundles into variants/*/*/repo/
```

CI uses Python 3.12 and Java 21 (Temurin). Scoring needs only Python 3.

## Build/test/lint commands

```bash
python3 scripts/results.py             # recount RESULTS.md from runs/ and the keys
python3 scripts/results.py --check     # what the score workflow runs
sh scripts/gate.sh                     # before publishing anything: names, paths, secrets
```

Platform and baseline test suites: see `.github/workflows/platform.yml`. After `sh scripts/setup_tools.sh` it runs `platform/ci/run-tests.sh` for both apps from `platform/` (with `JUNIT_JAR` and `PYTHON` pointing into `.tools/`), then `baselines/fixtures/build.py`, then `KB_FAKE_AWS=1 .tools/venv/bin/python -m pytest -q baselines/tests`.

No lint command is defined in CI or in top-level config files.

## Conventions

- Agent-authored PRs are opened from the `son-of-anton-ai` account.
- Every PR body states what changed, why, and the test evidence (the commands run and their results).
- Link the Linear issue the change belongs to.
- Never commit secrets, tokens, keys or `.env` files.
- `AGENTS.md` is the only agent-instructions file in this repo. Do not add `CLAUDE.md` or other tool-specific instruction files.
- Never edit published verdicts in `runs/`; a fresh replication writes to its own runs directory (`--runs-dir`), as the README describes.
- Use the frozen prompts in `baselines/prompts/` unchanged; a new prompt is a new file with its SHA-256 recorded in each verdict.
- This repo is public: run `sh scripts/gate.sh` before pushing.
